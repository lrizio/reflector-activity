1. What it does

You pick a mode (D-STAR, YSF or DMR) and a time window (15, 30 or 60 minutes), and it lists the reflectors for that mode ranked by how active they have been. Use it to find a reflector that actually has people on it, instead of linking to an empty one.

It is a small program that runs on your PC. It collects activity in the background and shows it as a web page that only your own computer can open (http://localhost:8787).

It only knows what it has seen since it started. Leave it running for about 30 minutes before trusting a 30-minute average, and longer for the 60-minute view. A yellow banner at the top of the page tells you while it is still warming up. History is kept for 24 hours and survives restarts.

2. Quick start (Windows)

  1. Unzip the folder somewhere permanent, for example C:\ReflectorActivity. Don't run it from inside the zip file.
  2. Double-click start.cmd. A black window opens and your browser opens the page. Keep that window open while you use the app; closing it stops the app.
  3. First run only: it asks for your callsign. Type your own and press Enter, or just press Enter to skip. See Settings for what this is used for.
  4. If Windows asks whether to let node.exe use the network, choose Allow (private networks is enough). The app needs this to talk to the reflectors.
  5. If the browser doesn't open by itself, go to http://localhost:8787.

To stop it: click the black window and press Ctrl+C, or close the window. To start it again later, double-click start.cmd again.

Windows SmartScreen or your antivirus may warn about runtime\node.exe because it is a program from a downloaded zip. It is the official Node.js runtime, which the app runs on. If you would rather not trust it, install Node yourself (see section 8) and delete the runtime folder.

4. What the numbers mean, per mode

The three systems publish very different amounts of information, so "activity" is measured differently for each. This matters when you compare tabs.

D-STAR

  • Tx/30m — transmissions per 30 minutes. Stations — different callsigns that transmitted. Linked — nodes or users currently connected.
  • Covers about 560 XLX reflectors (each XLX also answers as XRF, DCS and REF with the same number, so those are included) and about 45 original DPlus REF reflectors that publish a public web dashboard. Reflectors that don't answer or don't publish anything can't be seen.
  • The module shown next to a name (for example XLX307 · mod C) is its busiest module. Expand the row for all of them.
  • Watch the Stations column. One stuck or chatty node can produce hundreds of transmissions from a single callsign. A busy reflector has several different callsigns.

DMR

  • Rows are talkgroups (TG numbers), with the name TGIF gives them.
  • Covers the TGIF network only. BrandMeister, DMR+ and others are not included, so a talkgroup that is busy elsewhere may not appear.
  • Only talkgroups heard during the last hour are listed.

YSF

  • YSF reflectors do not publish who is talking, only how many users are connected. So there are two kinds of rows:
  • The 50 busiest reflectors (by connected users) are "listened to": the app connects to them silently and counts real transmissions, so they have real Tx/30m and Stations values. Which 50 is re-chosen every 15 minutes.
  • All other reflectors show a dash for Tx and Stations and only have Avg users (average connected users in the window). Click the "Avg users" heading to sort the whole list by that.
  • Connected users is not the same as talking. Bridges and always-linked nodes count as users even when nobody is speaking, so some reflectors sit at a high, constant user count (999 is a common ceiling). Compare Tx and Stations before choosing.
  • Without a callsign configured, the listener is off and the YSF tab ranks by connected users only.

5. Settings

Settings live in config.json in the app folder. Edit it with Notepad and restart the app. Delete the file to be asked again at the next start.

{
  "callsign": "N0CALL",
  "listenTop": 50
}
SettingMeaning
callsignUse your own callsign. It is only used to identify the YSF listener to reflectors (see below). Leave it empty ("") to turn the YSF listener off completely.
listenTopHow many of the busiest YSF reflectors to listen to. Default 50, maximum 200. Set 0 to turn the listener off. Lower is gentler on the network.

Other options (environment variables)

VariableMeaning
PORTWeb page port. Default 8787. Use another if something else is using it, for example in a command prompt: set PORT=8800 then start.cmd.
NO_BROWSERSet to anything (for example set NO_BROWSER=1) to stop start.cmd opening the browser.

6. What it does on the network (please read)

The app talks to public reflectors and websites that volunteers run. It is designed to be light, but you should know what it does, and please don't make it heavier.

ModeTraffic
D-STAR (XLX)One small status request to each XLX reflector about every 30 seconds.
D-STAR (REF)One web page request to each of about 45 reflector dashboards about once a minute. A list is refreshed weekly.
YSF statusOne small status request per reflector about once a minute (about 1,700 reflectors).
YSF listenerConnects to up to listenTop reflectors as a silent, listen-only station using your callsign, sending a keep-alive about every 5 seconds. You will appear in those reflectors' connected-user lists. It never transmits.
DMRA single live connection to TGIF's public last-heard feed, the same one their web page uses.
  • Use your own callsign in the YSF settings. Don't use someone else's or a made-up one, and don't share your config file.
  • If a reflector operator doesn't want listeners, set listenTop to 0. Reflectors can block callsigns.
  • One copy per person is plenty. Running many copies, or shortening the polling intervals in the code, multiplies the load on other people's servers.
  • When it fetches REF dashboards and host lists, the app identifies itself as "reflector-activity" so operators can see what it is.

7. Troubleshooting

ProblemWhat to try
The black window closes immediatelyIt shouldn't: it stays open and shows an error. If it closes anyway, you probably ran it from inside the zip. Unzip the folder first.
Port 8787 is already in useThe app is probably already running (look for another black window), or another program uses that port. Close the other copy, or start with a different PORT (see Settings).
The page says "Can't reach the local server"The black window was closed, or the app stopped. Look at the window for an error message, then run start.cmd again.
The list is empty or very short at the startNormal for the first minute or two, and the averages need about 30 minutes. Tick "show idle" to see reflectors even without activity.
No data at all for D-STAR or YSFA firewall is probably blocking the app. Allow node.exe in Windows Firewall (private networks), and check that your router or security software doesn't block outgoing UDP.
DMR tab is emptyCheck your internet connection. The black window shows [tgif] connected when the feed is up.
YSF tab shows only "Avg users"The listener is off. Put your callsign in config.json and restart.
A reflector I know is busy doesn't appearIt may not publish status or may not be covered (see section 4). The page only knows what the sources publish.
Weird or stale data after a crashThe app repairs a damaged history file by itself. To start completely fresh, stop the app and delete the folder %LOCALAPPDATA%\ReflectorActivity (Mac/Linux: ~/.reflector-activity).

The black window's messages are also saved in server.log in the same folder (%LOCALAPPDATA%\ReflectorActivity). If you report a problem, include the last lines of that file.

8. Mac, Linux, or your own Node

The Windows zip carries its own copy of Node.js in the runtime folder, so nothing needs installing. On other systems, or if you prefer your own Node:

  1. Install Node.js 24 or newer from nodejs.org. (The app uses Node's built-in SQLite, which older versions lack.)
  2. In the app folder run npm install --omit=dev once (not needed if node_modules is already there).
  3. Start it with ./start.sh (Mac/Linux) or start.cmd (Windows, uses your Node if there is no runtime folder). Or run node server.mjs directly and open http://localhost:8787.

9. Data sources, privacy and disclaimer

Where the data comes from

  • D-STAR: the public XLX reflector list at xlxapi.rlx.lu and each reflector's own status feed; and the public "DPLUS Dashboard" web pages of REF reflectors, found from Pi-Star's host list.
  • YSF: the reflector list from DVRef (dvref.com), downloaded from Pi-Star's public mirror, then each reflector's status feed and, for the busiest, its voice stream.
  • DMR: the TGIF Network's public last-heard feed (tgif.network).

Credit and thanks to the volunteers who run these reflectors and services. Their data stays theirs; the app only reads what they publish.

Bundled software

The Windows zip includes the Node.js runtime in the runtime folder. Node.js is MIT-licensed; its licence and third-party notices are in runtime\LICENSE-node.txt. The libraries in node_modules carry their own licences in their folders.

Privacy

  • Everything is stored on your PC, in the data folder. Nothing is sent to the author or any third party.
  • The web page only answers to your own computer; other devices on your network can't open it.
  • The only thing that identifies you to anyone is your callsign, sent to the YSF reflectors the listener joins (only if you set one).

Limits and disclaimer

  • The numbers are estimates built from public, unofficial sources that can change or disappear without notice. They show where activity is likely, not an exact count.
  • If a source changes its format or blocks access, that part of the app will stop updating.
